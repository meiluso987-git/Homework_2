a. Simulation function

#' Title Simulate a 2D random walk with momentum
#'
#' Simulates a particle moving in two dimensions on a square lattice.
#' The first step chooses one of four directions uniformly at random.
#' From the second step onward, 
#' with probability p the particle continues in the same direction as previous, 
#' and with probability \(1-p\) it re-randomizes uniformly among the four directions.
#' 
#' @param n Integer. Number of steps to take.
#' @param p Numeric. Momentum probability, between 0 and 1.
#'
#' @returns A numeric vector of length 2 giving the final coordinates
#' @export
#'
#' @examples
#' momentum_walk(10, 0.6)
momentum_walk <- function(n, p) {
  if (n < 1 || n != round(n)) stop("n must be a positive integer")
  if (p < 0 || p > 1) stop("p must be between 0 and 1")

  dirs <- list(c(1, 0), c(-1, 0), c(0, 1), c(0, -1))  # 4 direction

  # First step
  d <- sample(1:4, 1)
  x <- dirs[[d]][1]
  y <- dirs[[d]][2]

  # Second step
  for (i in 2:n) {
    if (runif(1) >= p) {
      d <- sample(1:4, 1)
    }
    x <- x + dirs[[d]][1]
    y <- y + dirs[[d]][2]
  }

  c(x, y)
}

b. Implement the simulation

Version 1: for loop

#' Title Simulate a 2D random walk with momentum (for-loop version)
#' 
#' First step chooses one of four directions uniformly. 
#' From step 2 onward,
#' with probability p the particle keeps the previous direction; 
#' with probability 1-p it re-randomizes uniformly among the four directions.
#'
#' @param n Integer. Number of steps, must be >= 1.
#' @param p Numeric. Momentum probability, between 0 and 1.
#'
#' @returns A numeric vector c(x, y) of the final position.
#' @export
#'
#' @examples
#' momentum_walk1(10, 0.6)
momentum_walk1 <- function(n, p) {
  if (n < 1 || n != round(n)) stop("n must be a positive integer")
  if (p < 0 || p > 1) stop("p must be between 0 and 1")

  dirs <- list(c(1, 0), c(-1, 0), c(0, 1), c(0, -1))
  d <- sample(1:4, 1)
  x <- dirs[[d]][1]; y <- dirs[[d]][2]

  for (i in 2:n) {
    if (runif(1) >= p) d <- sample(1:4, 1)
    x <- x + dirs[[d]][1]
    y <- y + dirs[[d]][2]
  }
  c(x, y)
}

Version 2: Reduce (apply-family)

#' Title Simulate a 2D random walk with momentum (Reduce version)
#' 
#' using Reduce(). 
#' which applies the step-update function repeatedly across n-1 remaining steps.
#'
#' @param n Integer. Number of steps, must be >= 1.
#' @param p Numeric. Momentum probability, between 0 and 1.
#'
#' @returns A numeric vector c(x, y) of the final position.
#' @export
#'
#' @examples
#' momentum_walk2(10, 0.6)
momentum_walk2 <- function(n, p) {
  if (n < 1 || n != round(n)) stop("n must be a positive integer")
  if (p < 0 || p > 1) stop("p must be between 0 and 1")

  dirs <- list(c(1, 0), c(-1, 0), c(0, 1), c(0, -1))

  # First step
  d0 <- sample(1:4, 1)
  state <- c(x = dirs[[d0]][1], y = dirs[[d0]][2], dir = d0)

  # Second step
  step <- function(state, dummy) {
    if (runif(1) >= p) state["dir"] <- sample(1:4, 1)
    state["x"] <- state["x"] + dirs[[state["dir"]]][1]
    state["y"] <- state["y"] + dirs[[state["dir"]]][2]
    state
  }

  final_state <- Reduce(step, init = state, x = 1:(n - 1))
  as.vector(c(final_state["x"], final_state["y"]))
}

Briefly explain the logic of each implementation：

‘momentum_walk1’ uses an explicit for‑loop. It samples the first‑step direction, then updates position: with probability (1-p) it picks a new direction, and with probability p it retains the old direction for momentum, before updating coordinates.

‘momentum_walk2’ uses ‘Reduce()’. The whole walk state (position + direction) is wrapped in one vector. A step‑update function modifies this state for one move, and ‘Reduce’ repeatedly applies this function over all remaining steps to produce the final position.

What I did:

I used ‘set.seed(integer)’ immediately before running the random‑walk simulation. And then use ‘momentum_walk1()’ and ‘momentum_walk1()’ with identical function arguments.

Seed values 42 and 123 are arbitrary integers; any valid integer would serve the same purpose. After setting the same seed, the simulation produced exactly matching final‑position outputs on repeated runs.

Why it works:

R does not produce truly random numbers; it uses a deterministic pseudo‑random‑number algorithm. Once a seed is fixed, every subsequent call to random‑generating functions will return the identical sequence of random numbers.

As a result, the sequence of directions chosen inside the momentum walk stays unchanged, so the simulated walk ends at the same coordinate.

This achieves reproducibility.

From the output, distance grows as p increases.

  1. Does increasing momentum appear to increase or decrease the final distance?

Increasing momentum appears to increase the final distance from the starting point.

  1. Explain your reasoning (optional).

Higher momentum makes the walker persist in the same direction for many steps. Steps add together instead of cancelling out.

When (p=0), direction is re‑sampled every step; many steps point backward, so displacement remains small. Larger p produces larger displacement.

Calculate the skewness:

raw_vars <- c("view_count", "like_count", "dislike_count", "favorite_count", "comment_count")

#' Title Calculate sample skewness
#' 
#' Computes the sample skewness coefficient of a numeric vector, ignoring missing values. 
#' A value near 0 indicates approximate symmetry; 
#' large positive values indicate right (positive) skewness.
#'
#' @param x Numeric vector. May contain NA values, which are removed.
#'
#' @returns Numeric scalar: the sample skewness. 
#' @export
#'
#' @examples
#' calc_skewness(c(1, 2, 3, 4, 5))    # symmetric
calc_skewness <- function(x) {
  x <- x[!is.na(x)]
  n <- length(x)
  if (n == 0) return(NA) 
  mean_x <- mean(x)
  sd_x <- sd(x)
  if (is.na(sd_x) || sd_x == 0) return(0)
  (sum((x - mean_x)^3) / n) / (sd_x^3)
}
